  HUSARIABEATS.COM — WEBSITE ARCHITECTURE & DEPLOYMENT PLAN

OVERVIEW
--------
Educational companion website for the Husaria Beats YouTube channel.
Bilingual (PL/EN), timeline-based, community voting, YouTube embeds.
Domain: husariabeats.com
Server: self-hosted Linux server (existing nginx + Cloudflare DNS)


TECH STACK
----------
Frontend  : Next.js 14 (App Router, TypeScript, i18n routing)
API       : FastAPI (Python)
Database  : PostgreSQL 16
Cache     : Redis 7 (rate-limiting for votes)
Containers: Docker Compose
TLS/Proxy : nginx on HOST (Let's Encrypt cert, same pattern as ticker-tap)
DNS       : Cloudflare proxied A record → server IP


PORTS (host-bound, localhost only)
-----------------------------------
Next.js frontend  : 127.0.0.1:3001   (avoids clashes)
FastAPI backend   : 127.0.0.1:8001   (ticker-tap uses :8000 — no clash)
Admin panel       : 127.0.0.1:3002   (internal only, Cloudflare Access protected)
PostgreSQL        : internal Docker network only (no host port)
Redis             : internal Docker network only (no host port)

DATABASE SCHEMA (db/init.sql)
------------------------------
-- Song status tracking
CREATE TABLE songs (
  slug        VARCHAR(100) PRIMARY KEY,
  title_pl    VARCHAR(200),
  title_en    VARCHAR(200),
  status      VARCHAR(50) DEFAULT 'scaffold',
              -- scaffold|audio_ready|sync_done|render_done|scheduled|released
  album_slug  VARCHAR(100),
  year_event  INTEGER,
  era         VARCHAR(50),
              -- medieval|partitions|wwi|wwii|cold_war|modern
  youtube_id_pl  VARCHAR(20),
  youtube_id_en  VARCHAR(20),
  image_path  TEXT,
  release_date TIMESTAMPTZ,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- Album tracking
CREATE TABLE albums (
  slug         VARCHAR(100) PRIMARY KEY,
  title        VARCHAR(200),
  description  TEXT,
  status       VARCHAR(50) DEFAULT 'planned',
               -- planned|in_production|released
  release_date TIMESTAMPTZ,
  cover_art    TEXT
);

-- Release queue (for automated publishing)
CREATE TABLE release_queue (
  id            SERIAL PRIMARY KEY,
  song_id       VARCHAR(100) REFERENCES songs(slug),
  scheduled_at  TIMESTAMPTZ NOT NULL,
  status        VARCHAR(50) DEFAULT 'queued',   -- queued|released|skipped
  platforms     TEXT[] DEFAULT '{youtube,facebook,instagram,tiktok}',
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

-- Configurable settings (change without redeploying)
CREATE TABLE settings (
  key   VARCHAR(100) PRIMARY KEY,
  value TEXT
);
INSERT INTO settings VALUES
  ('release_min_gap_hours', '24'),   -- min hours between auto-releases
  ('release_daily_limit',   '1'),    -- max songs released per day
  ('auto_release_enabled',  'true'); -- global kill switch

-- Community voting
CREATE TABLE topics (
  id          SERIAL PRIMARY KEY,
  title       VARCHAR(200) NOT NULL,
  description TEXT,
  status      VARCHAR(50) DEFAULT 'open',  -- open|in_development|released
  planned_release VARCHAR(50),             -- e.g. "Jun 2026"
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE votes (
  id          SERIAL PRIMARY KEY,
  topic_id    INTEGER REFERENCES topics(id),
  email_hash  VARCHAR(64) NOT NULL,         -- SHA-256, never store raw email
  voted_at    TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_votes_topic ON votes(topic_id);
CREATE INDEX idx_votes_email_hash ON votes(email_hash);


RELEASE AUTOMATION ARCHITECTURE
---------------------------------
Single source of truth: PostgreSQL DB (songs table + release_queue)
Admin panel manages the queue and settings.
n8n (self-hosted at n8n.your-automation-host.example) executes the release chain.

RELEASE CHAIN (triggered by n8n daily cron 09:00):
  1. Check release_queue for today's scheduled items
  2. Check settings: auto_release_enabled=true, within daily_limit
  3. Upload MP4 → YouTube (via YouTube Data API v3, OAuth stored in n8n)
  4. Set YouTube publish time, add to playlist
  5. On YouTube publish → post to Facebook Page (Graph API)
  6. On YouTube publish → post to Instagram Business (Graph API)
  7. On YouTube publish → post to TikTok (Content Posting API)
  8. Update songs.status → 'released' in DB
  9. Update release_queue.status → 'released'
  10. If voting topic exists for this song → close it, add planned_release badge
  11. Website timeline auto-reflects new status (reads DB, no manual update)

SEMI-AUTOMATED LOCAL SCRIPT:
  python scripts/release.py --song kosacki --date 2026-05-15
  → Updates DB song status + release date
  → Adds entry to release_queue
  → Generates YouTube title/description from template (PL+EN)
  → Prepares DistroKid CSV row
  → Drafts social post text to file
  → Closes voting topic

DISTROKIT: no API — script prepares CSV, human submits (~1 day before release date)

ALBUM RELEASE CADENCE:
  Admin sets: start date + gap (hours) in settings table
  Queue auto-fills from that date forward
  Change release_min_gap_hours → cadence changes immediately, no redeploy
  Kill switch: set auto_release_enabled=false to pause everything


ADMIN PANEL — CLOUDFLARE ACCESS (internal only)
------------------------------------------------
URL: admin.husariabeats.com (or husariabeats-admin.com — TBD)
Protection: Cloudflare Zero Trust → Access → Self-hosted application
            Policy: Allow → Email → <ADMIN_ACCESS_EMAIL>
            Nobody else can reach URL even if they know it
            Login: Cloudflare emails one-time code (no password to manage)

nginx config for admin:
  proxy_pass http://127.0.0.1:3002
  (Cloudflare Access validates before any request reaches nginx)

Admin panel functions:
  - Release queue: drag/drop song order, set start date, set gap hours
  - Song management: update status, upload cover art, edit metadata
  - Voting dashboard: view top topics, assign to album, set planned_release
  - Settings: change release_daily_limit, release_min_gap_hours, kill switch


NGINX CONFIGS

/etc/nginx/sites-available/husariabeats.com.conf
------------------------------------------------
# HTTP → HTTPS redirect
server {
    listen 80;
    listen [::]:80;
    server_name husariabeats.com www.husariabeats.com;

    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 301 https://$host$request_uri; }
}

# HTTPS
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name husariabeats.com www.husariabeats.com;

    ssl_certificate     /etc/letsencrypt/live/husariabeats.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/husariabeats.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;
    ssl_session_cache   shared:SSL:10m;
    ssl_session_timeout 1d;
    ssl_stapling        on;
    ssl_stapling_verify on;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    # NOTE: X-Frame-Options DENY intentionally omitted — YouTube embeds need frames

    client_max_body_size 5m;

    # API — FastAPI container
    location /api/ {
        proxy_pass         http://127.0.0.1:8001;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }

    # Frontend — Next.js container
    location / {
        proxy_pass         http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade    $http_upgrade;
        proxy_set_header   Connection "upgrade";
        proxy_set_header   Host       $host;
        proxy_set_header   X-Real-IP  $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}

DEPLOYMENT STEPS (run once on server)
--------------------------------------
# 1. Clone / create project folder
mkdir -p ~/docker/husariabeats
cd ~/docker/husariabeats

# 2. Cloudflare DNS:
#    A record: husariabeats.com → server IP (orange cloud)
#    A record: admin.husariabeats.com → server IP (orange cloud)
#    SSL/TLS mode: Full (strict)
#    Zero Trust → Access → add application for admin.husariabeats.com
#                         policy: Allow email = <ADMIN_ACCESS_EMAIL>

# 3. Get TLS cert (covers both subdomains)
sudo certbot --nginx -d husariabeats.com -d www.husariabeats.com -d admin.husariabeats.com

# 4. Enable nginx configs
sudo ln -s /etc/nginx/sites-available/husariabeats.com.conf /etc/nginx/sites-enabled/
sudo ln -s /etc/nginx/sites-available/husariabeats-admin.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo nginx -s reload

# 5. Create .env from example
cp .env.example .env
# Fill in: POSTGRES_USER, POSTGRES_PASSWORD, SECRET_KEY, RESEND_API_KEY

# 6. Start all containers
docker compose up -d

# 7. Verify
docker compose ps
curl -I https://husariabeats.com
curl -I https://admin.husariabeats.com  # should require Cloudflare login

------------------------------------------
1. GOOGLE CLOUD — YouTube Data API:

   - Create OAuth 2.0 credential → Web Application
   - Redirect URI: https://n8n.your-automation-host.example/rest/oauth2-credential/callback
   - Copy Client ID + Secret → add to n8n Google credential
   - Authorize once in n8n → refresh token stored automatically
   - No billing needed, free quota (10,000 units/day) is sufficient

2. META (Facebook + Instagram):
   - developers.facebook.com → New App → Business
   - Add permissions: pages_manage_posts, instagram_content_publish
   - Instagram Business account must be linked to Facebook Page
   - App Review required before going live (1-2 week process)
   - Add credentials to n8n Facebook Graph API credential

3. TIKTOK:
   - developers.tiktok.com → Create app
   - Request scope: video.publish
   - Submit for TikTok audit (required for public posts — can take weeks)
   - Start this process EARLY — apply before ZAPOMNIANI release (Jun 2026)
   - Add credentials to n8n TikTok credential

4. RESEND (email for voting magic links):
   - resend.com → Create account → Get API key
   - Verify domain: husariabeats.com (add DNS TXT record in Cloudflare)
   - Free tier: 3,000 emails/month — sufficient
   - Add RESEND_API_KEY to .env

5. CLOUDFLARE ZERO TRUST:
   - dash.cloudflare.com → Zero Trust → Access → Applications
   - Add Self-hosted app → domain: admin.husariabeats.com
   - Policy: Allow, Email = <ADMIN_ACCESS_EMAIL>
   - Free tier: 50 users — sufficient

KEY DESIGN DECISIONS
--------------------
- Language in URL: /pl/... and /en/... (SEO + shareable links)
- Language toggle drives YouTube embed src per song (PL vs EN video ID)
- songs.json schema: { slug, titlePL, titleEN, yearEvent, era,
  youtubeIdPL, youtubeIdEN, imagePath, summaryPL, summaryEN,
  sourcesPL[], sourcesEN[], albumSlug }
- Voting: email hash stored (SHA-256), never raw email
  Redis key = hash:topicId with 24hr TTL; upvote only
- Albums: status = released | in_production | planned
  Planned albums show countdown to releaseDate instead of cover art
- DB = single source of truth for all status; website reads it live
  No manual JSON edits needed after songs are released
